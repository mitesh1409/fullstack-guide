# Pagination in APIs

## 1. Page + Offset Pagination

**Concept:** The client specifies a page number and page size. The server skips a calculated number of rows and returns the next batch.

---

### Backend (SQL)

```sql
-- Page 1, 10 items per page
SELECT * FROM posts
ORDER BY created_at DESC
LIMIT 10 OFFSET 0;

-- Page 2
SELECT * FROM posts
ORDER BY created_at DESC
LIMIT 10 OFFSET 10;

-- Page N formula:
-- OFFSET = (page - 1) * pageSize
-- LIMIT  = pageSize
```

**Express.js API endpoint:**

```js
app.get('/posts', async (req, res) => {
  const page     = parseInt(req.query.page)     || 1;
  const pageSize = parseInt(req.query.pageSize) || 10;
  const offset   = (page - 1) * pageSize;

  const posts = await db.query(
    'SELECT * FROM posts ORDER BY created_at DESC LIMIT $1 OFFSET $2',
    [pageSize, offset]
  );

  const total = await db.query('SELECT COUNT(*) FROM posts');

  res.json({
    data:       posts.rows,
    page:       page,
    pageSize:   pageSize,
    total:      parseInt(total.rows[0].count),
    totalPages: Math.ceil(total.rows[0].count / pageSize),
  });
});
```

**API call:**

```
GET /posts?page=2&pageSize=10
```

**Response:**

```json
{
  "data": [...],
  "page": 2,
  "pageSize": 10,
  "total": 157,
  "totalPages": 16
}
```

---

### Frontend (React)

```jsx
function PostList() {
  const [page, setPage] = useState(1);
  const [data, setData] = useState([]);
  const [totalPages, setTotalPages] = useState(1);

  useEffect(() => {
    fetch(`/posts?page=${page}&pageSize=10`)
      .then(r => r.json())
      .then(res => {
        setData(res.data);
        setTotalPages(res.totalPages);
      });
  }, [page]);

  return (
    <div>
      {data.map(post => <PostCard key={post.id} post={post} />)}

      <div className="pagination">
        <button onClick={() => setPage(p => p - 1)} disabled={page === 1}>
          Previous
        </button>
        <span>Page {page} of {totalPages}</span>
        <button onClick={() => setPage(p => p + 1)} disabled={page === totalPages}>
          Next
        </button>
      </div>
    </div>
  );
}
```

## 2. Cursor-based Pagination

**Concept:** Instead of a page number, the client sends a **cursor** — a pointer to the last seen item (usually its `id` or `created_at`). The server fetches rows *after* that cursor.

---

### Backend (SQL)

```sql
-- First request (no cursor)
SELECT * FROM posts
ORDER BY id DESC
LIMIT 10;

-- Subsequent request — cursor is the last `id` from previous response (e.g. 482)
SELECT * FROM posts
WHERE id < 482          -- "give me rows BEFORE this id"
ORDER BY id DESC
LIMIT 10;
```

**Express.js API endpoint:**

```js
app.get('/posts', async (req, res) => {
  const limit  = parseInt(req.query.limit) || 10;
  const cursor = req.query.cursor; // last seen ID from previous page

  let posts;
  if (cursor) {
    posts = await db.query(
      'SELECT * FROM posts WHERE id < $1 ORDER BY id DESC LIMIT $2',
      [cursor, limit]
    );
  } else {
    posts = await db.query(
      'SELECT * FROM posts ORDER BY id DESC LIMIT $1',
      [limit]
    );
  }

  const rows       = posts.rows;
  const nextCursor = rows.length === limit ? rows[rows.length - 1].id : null;

  res.json({
    data:       rows,
    nextCursor: nextCursor,   // null means no more pages
    hasMore:    nextCursor !== null,
  });
});
```

**API calls:**

```
GET /posts?limit=10                  ← first page (no cursor)
GET /posts?limit=10&cursor=482       ← next page
GET /posts?limit=10&cursor=471       ← page after that
```

**Response:**

```json
{
  "data": [...],
  "nextCursor": 471,
  "hasMore": true
}
```

---

### Frontend — Infinite Scroll (React)

```jsx
function PostFeed() {
  const [posts, setPosts]         = useState([]);
  const [cursor, setCursor]       = useState(null);
  const [hasMore, setHasMore]     = useState(true);
  const [loading, setLoading]     = useState(false);

  const loadMore = async () => {
    if (loading || !hasMore) return;
    setLoading(true);

    const url = cursor
      ? `/posts?limit=10&cursor=${cursor}`
      : `/posts?limit=10`;

    const res  = await fetch(url).then(r => r.json());

    setPosts(prev => [...prev, ...res.data]);  // append, don't replace
    setCursor(res.nextCursor);
    setHasMore(res.hasMore);
    setLoading(false);
  };

  useEffect(() => { loadMore(); }, []); // load first page on mount

  return (
    <div>
      {posts.map(post => <PostCard key={post.id} post={post} />)}
      {hasMore && (
        <button onClick={loadMore} disabled={loading}>
          {loading ? 'Loading...' : 'Load More'}
        </button>
      )}
      {!hasMore && <p>You've reached the end!</p>}
    </div>
  );
}
```

### Why Cursor-based is Better for Large Datasets

Here's the core problem with `OFFSET`:

```sql
-- To get page 10,000 with 10 items per page:
SELECT * FROM posts ORDER BY created_at DESC LIMIT 10 OFFSET 99990;
```

The database **scans and discards 99,990 rows** just to return 10 rows (99,991 to 100,000). This gets slower the deeper you go.

| Problem | OFFSET | Cursor |
|---|---|---|
| **Deep page performance** | Scans all skipped rows — O(n) | Jumps directly via index — O(log n) |
| **New row inserted mid-session** | Row shifts cause duplicates/skips | Unaffected — anchored to a fixed ID |
| **SQL used** | `LIMIT x OFFSET y` (full scan) | `WHERE id < cursor LIMIT x` (index seek) |
| **Can jump to page 500?** | Yes | No — forward/backward only |
| **Total count needed?** | Yes (expensive `COUNT(*)`) | No |
| **Best UI pattern** | Numbered pages, admin tables | Infinite scroll, feeds, timelines |

The cursor query `WHERE id < 482` uses a **B-tree index** on `id`, making it an instant seek regardless of whether you're on page 1 or page 100,000. That's the fundamental advantage.
